# 설계 검토 기록: SWE.2 아키텍처 / SWE.3 상세 설계

| 항목 | 내용 |
|---|---|
| 문서 ID | DRV-ECL-001 |
| 검토 대상 | SWA-ECL-001, SWD-ECL-001, SAP-ECL-001 (모두 v1.0 후보) |
| 기준 문서 | SWRS-ECL-001 v1.1, QA-ECL-001 |
| 검토 방식 | 독립 검토. 작성자의 문맥 없이 시작한 별도 AI 에이전트가 수행했다. 의사코드를 SWRS 수용 기준에 대입해 손으로 실행했다 |
| 한계 | 사람 검토자의 서명 검토가 아니다. G2 수용(OEM-A SW Architect)과 사내 기술 검토 서명은 별도로 필요하다 |

## 1. 검토 이력

| 회차 | 결과 |
|---|---|
| 1차 | 지적 15건 (주요 4, 보통 8, 경미 3). 기준선 불가 |
| 2차 | DR-01~15 모두 해소. 새 지적 3건 (보통 3)과 경미 메모 1건. 판정: BL-SWA-1.0 확정 가능. BL-SWR-1.1과 BL-SWD-1.0은 DR-16·17 반영 후 작성자 확인으로 확정 가능 |
| 작성자 확인 | DR-16~18과 경미 메모 반영을 확인 (아래 표) |

## 2. 지적 사항과 조치

| ID | 심각도 | 지적 요지 | 조치 | 상태 |
|---|---|---|---|---|
| DR-01 | 주요 | 시각 경계 판정이 float 뺄셈에 의존해 정확히 0.200 s, 10.0 s, 1.0 s에서 결과가 입력값에 따라 달라짐 | 내부 시각을 정수 µs로 처리 (AP-02, AD-05, DD-05, 상수 µs화) | 해소 |
| DR-02 | 주요 | 큰 정수(10^400)에서 `math.isfinite`가 OverflowError를 내 응답 없이 연결이 끊김 | int는 isfinite 없이 정확한 비교, now_s 범위 0~1e9 (U1 `_number`, DD-01) | 해소 |
| DR-03 | 주요 | DEGRADED 중 접근위험 FALSE에서 override 기억을 지우지 않아 옛 override가 되살아남 | 지움 조건을 "유효값 FALSE"로 바꿈 (U3 `_clear_memory`) | 해소 |
| DR-04 | 주요 | PENDING 중 운전자 해제를 두고 SWR-004와 SWR-008이 충돌, 세 규칙 조합 기대값 없음 | SWRS CR-02, DI-04 | 해소 |
| DR-05 | 보통 | `or`로 None을 판정해 now 0.0에서 래치 시간 계산이 틀림 | None 판정 규칙 PS-07, `_update_latch` 명시 | 해소 |
| DR-06 | 보통 | 구성요소 간 타입 의존이 SWA 의존도와 다름 | 구성요소 간 타입을 C0으로 이동, 인터페이스 표 추가 (SWA 2.3) | 해소 |
| DR-07 | 보통 | ValueError만 400, 나머지 예외는 응답 없이 끊김. 키 누락·크기 제한 미추적 | `TickRejected`, 나머지 500, DD-02~04, DD-06 | 해소 |
| DR-08 | 보통 | 시뮬레이터가 같은 unlock을 반복 전송해 override가 저절로 생김. timestamp 미정의 | 명령 1회 전송, timestamp_s=now_s, 정수 틱 카운터 | 해소 |
| DR-09 | 보통 | 기록 조건 "바뀐 것" 범위와 초기 reason 불명확 | SWRS CR-03, `_record_key`, 초기 reason IGNITION_OFF | 해소 |
| DR-10 | 보통 | SWR-013·010·015·020 할당과 역추적 누락 | SWA 6장, SWD 11장 양방향 표 | 해소 |
| DR-11 | 보통 | 브라우저 화면의 안전 경계, 사전 존재 SW, 도구 신뢰 수준 논거 없음 | 화면을 SW 경계 밖으로 정의 (SWA 4.1), SWA 4.4, SAP 7절 | 해소 |
| DR-12 | 보통 | Table 1의 1i 누락, 등급 오류 가능성, Python 부분집합 미정의, 금지 API 수동 검출 | SAP 2·3·4절 (PS-01~12, TID251, mypy 강화) | 해소 |
| DR-13 | 경미 | 복잡도 10을 지키기 위한 함수 분할과 500 주입 방법 미정의 | 보조 함수와 예상 복잡도 명시, `_serialize` monkeypatch | 해소 |
| DR-14 | 경미 | frozen 타입 안의 가변 dict, 기록 추가 순서 불일치 | MappingProxyType, 반영 단계에서 기록 추가 | 해소 |
| DR-15 | 경미 | 설계 해석이 기록되지 않음 | SWD 12장 DI-01~05, Q-22 | 해소 |
| DR-16 | 보통 | 시계 해상도·범위 제약(DD-01)이 SWRS에 없어 SWE.6 시험과 불일치 가능 | SWRS CR-04 | 해소 (작성자 확인) |
| DR-17 | 보통 | 비 UTF-8 본문, 과도한 중첩 JSON이 400 대신 500 | `_read_json_body`에서 ValueError·RecursionError를 400으로, 시험 추가, SWRS CR-04 | 해소 (작성자 확인) |
| DR-18 | 보통 | Web 검증이 경계 밖 화면에 의존 | Web 시험 판정을 API 응답으로 한정 (SWA 4.1, SWD 10장, SAP 7절) | 해소 (작성자 확인) |
| 메모 | 경미 | SWA 4.4 허용 목록과 SAP 금지 목록 표현 불일치, 모듈 누락 | SWA 4.4를 허용 목록으로 정리하고 모듈 추가, SAP 리뷰 체크리스트에 항목 추가 | 해소 (작성자 확인) |

## 3. 요구사항 변경 (BL-SWR-1.1)

설계 중 발견한 요구사항 문제는 SWRS 변경 요청으로 처리했다. 상세 내용은 RVW-ECL-001 3장(CR-01~CR-03)에 있다.

## 4. 결론

- 1차 15건과 2차 3건(DR-16~18), 경미 메모 1건을 모두 조치했다.
- 2차 판정에 따라 BL-SWA-1.0은 확정할 수 있다. BL-SWR-1.1과 BL-SWD-1.0은 DR-16·17을 반영하고 작성자가 확인해 확정할 수 있다.
- **남은 승인 절차:** 사내 기술 검토 서명과 OEM-A G2 수용(SW Architect)은 사람이 해야 한다.
