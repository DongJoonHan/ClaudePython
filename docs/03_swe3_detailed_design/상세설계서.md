|---|---|

| 버전 | 1.1 (BL-SWD-1.0 이후 구현 단계 변경 IC-01~06 반영) |

SWRS에는 없지만 설계에서 정해 추적하는 요구다.

| ID | 내용 | 상위 SWR |
|---|---|---|
| DD-01 | `now_s`는 int 또는 float(bool 제외)이고, 유한하며 0 ≤ now_s ≤ 1e9이다. `now_us = round(now_s × 1,000,000)`가 직전 now_us보다 커야 한다. 아니면 `TickRejectedError`를 낸다 | 015, 016 |
| DD-02 | `POST /api/tick` 본문에 `snapshot` 키가 없으면 `null`(입력 없음)과 같이 처리한다 | 015 |

| DD-06 | 틱 반영 후 응답 직렬화가 실패해 500이 나도 그 틱은 이미 반영돼 있다. 같은 now_s로 다시 보내면 DD-01에 따라 400이 된다 | 015 |

## 4. U1 입력 검증 (`validation.py`) — SWR-013

```python
def validate_snapshot(raw: object) -> ParsedInput
```

**알고리즘**
1. `raw is None` → `ParsedInput(present=False)` (나머지는 기본값: timestamp=None, 빈 SignalUpdate, invalid_fields=∅, command=None, command_invalid=False)
2. `raw`가 dict가 아니면 → `present=True`, `invalid_fields`에 모든 입력 키를 넣고, `timestamp=None`
3. `timestamp_s`는 `_number(v)`로, 각 필드는 `_parse_fields`에서 규칙 함수로 검사해 `SignalUpdate`를 만든다. 결과가 None인 필드의 입력 키를 `invalid_fields`에 넣는다. 누락 키는 실패다.
4. 명령: `driver_command` 키가 없거나 None이면 명령 없음. dict이고 세 필드가 모두 유효하면 `DriverCommand`, 그 밖에는 `command_invalid=True`.

**규칙 함수** (실패 시 None 반환. 유효한 값 중 None은 없으므로 표지로 쓸 수 있다)

| 함수 | 규칙 | 비고 |
|---|---|---|
| `_number(v)` | `type(v) is int`이면 그대로 통과(float 변환 없음). `type(v) is float`이면 `math.isfinite(v)` | 큰 정수에도 `OverflowError`가 나지 않는다 (DR-02) |
| `_speed(v)` | `_number` 통과 후 `SPEED_MIN_KPH <= v <= SPEED_MAX_KPH`, float로 변환 | int와 float 비교는 Python에서 정확하다 |
| `_strict_bool(v)` | `type(v) is bool` | |
| `_enum(enum_cls)` | `type(v) is str`이고 값 집합에 있음 | 클로저로 규칙 생성 |

**복잡도:** `validate_snapshot` 약 5, `_parse_command` 약 5, 규칙 함수 각 3 이하

**단위 시험 설계:**
- 필드별 값: 0.0, 300.0, −0.1, 300.1, NaN, ±inf, 10^400(int), True, "1", 누락
- enum: 목록 밖 값, 비문자열
- 명령: 필드별 누락·오류
- raw: 비-dict, None

## 5. U2 신호 추적 (`signals.py`) — SWR-007, 013

```python
@dataclass(frozen=True)
class TrackerState:
    values: Signals
    field_time_us: Mapping[str, int]   # MappingProxyType
    last_timestamp: float | int | None

def initial_tracker(now_us: int) -> TrackerState
def advance_signals(state: TrackerState, parsed: ParsedInput, now_us: int) -> tuple[TrackerState, SignalView]
```

**알고리즘**
1. `order_valid = parsed.present and parsed.timestamp is not None and (state.last_timestamp is None or parsed.timestamp > state.last_timestamp)`
2. order_valid이면 `_apply_update()`로 `values`를 바꾸고(필드마다 `_pick(새 값, 직전 값)`), `parsed.update`에서 None이 아닌 판정 필드의 `field_time_us`를 `now_us`로 바꾸며, `last_timestamp`를 갱신한다.
3. `fresh = frozenset(f for f in DECISION_FIELDS if now_us - field_time_us[f] <= STALE_LIMIT_US)`, `stale = len(fresh) != len(DECISION_FIELDS)`
4. `frame_confirmed = parsed.update.crash is CrashStatus.CONFIRMED` (순서 무관, Q-21. `values`에는 반영하지 않음)
5. `any_invalid = bool(parsed.invalid_fields) or parsed.command_invalid or (parsed.present and not order_valid)`
6. `command = parsed.command if order_valid else None`

`initial_tracker(now_us)`는 모든 판정 필드의 시각을 `now_us`(첫 틱)로 두고, `values=Signals()`로 둔다.

**보조 함수:** `_is_order_valid`, `_apply_update`, `_merge_values`, `_pick`. 복잡도는 각각 4 이하이다.

**단위 시험 설계:**
- 경계: 경과 200,000 µs는 정상, 200,001 µs는 STALE
- now_s 0.7 → 0.9 쌍 (float 오차가 나는 쌍이지만 정수 µs라 정상이어야 함)
- timestamp가 같음·과거·오류이면 값과 시각이 바뀌지 않음
- 특정 필드만 계속 오류이면 그 필드 때문에 STALE이 됨
- 순서 무효 프레임의 CONFIRMED가 `frame_confirmed`에 잡힘

## 6. U3 안전 상태 (`safety_state.py`) — SWR-005~007, 009, 013, 020, 021

```python
@dataclass(frozen=True)
class SafetyState:
    latched: bool = False
    release_since_us: int | None = None   # 래치 해제 조건이 연속 성립하기 시작한 시각
    mem_left: DoorMemory = DoorMemory()
    mem_right: DoorMemory = DoorMemory()

def determine_state(latched: bool, stale: bool, sensor_fault: bool, ignition_on: bool) -> State
def advance_safety(state: SafetyState, view: SignalView, now_us: int) -> tuple[SafetyState, State]
def apply_memory(state: SafetyState, decision: Decision) -> SafetyState
```

**`determine_state`** — SWRS 4장 결정표를 위에서부터 적용한다: latched → EMERGENCY, stale → DEGRADED, sensor_fault → FAULT, not ignition_on → OFF, 그 외 → NORMAL. 복잡도 5.

**`advance_safety`** — 보조 함수 2개를 차례로 호출한다. 복잡도 2.
1. `latched, since = _update_latch(state, view, now_us)`
2. `st = determine_state(latched, view.stale, view.values.sensor_fault, view.values.ignition_on)`
3. `mem_l = _clear_memory(state.mem_left, view.values.approach_left, st)`, 오른쪽도 같다.

**`_update_latch(state, view, now_us) -> tuple[bool, int | None]`** — 복잡도 약 6

```text
if view.frame_confirmed or view.values.crash is CONFIRMED:
    return True, None                                   # 설정 (또는 유지)
if not state.latched:
    return False, None
release_ok = {"ignition_on", "crash"} <= view.fresh and not view.values.ignition_on
if not release_ok:
    return True, None                                   # 연속 계산 끊김
since = state.release_since_us if state.release_since_us is not None else now_us
if now_us - since >= LATCH_RELEASE_US:
    return False, None                                  # 해제
return True, since
```

**`_clear_memory(mem, approach, st) -> DoorMemory`** — 복잡도 2

```text
if st is OFF or not approach:  return DoorMemory()      # SWR-006, Q-20, Q-22
return mem
```

- `approach`는 유효값이다. 유효값은 순서 유효 프레임으로만 바뀌므로, DEGRADED 중에 받은 유효한 FALSE로도 지운다(DR-03).

**`apply_memory`** — 중재 결과의 `memory`를 SafetyState에 넣는다.

**단위 시험 설계:**
- 래치 해제 경계: 0.99 s는 유지, 1.00 s는 해제
- 조건이 중간에 끊기면 다시 셈. ignition_on이나 crash가 STALE이면 세지 않음
- 시작 시각이 0인 경우 (DR-05 회귀 시험)
- 결정표 행마다, 그리고 겹치는 행
- DEGRADED 중 접근위험 FALSE → TRUE 시나리오 (DR-03 회귀 시험)

## 7. U4 판정 중재 (`arbitration.py`) — SWR-001~005, 008, 009, 017~019

```python
def arbitrate(inp: ArbitrationInput) -> Decision      # 도어마다 _decide_door 호출
```

**`_decide_door(door, inp) -> DoorDecision`** — 1~5순위 (ASIL B). 복잡도 약 7

```text
prev, mem = 해당 도어 직전 출력, 기억
if inp.state is EMERGENCY:   return (RELEASE, CRASH_CONFIRMED, 1, mem)
if inp.state is DEGRADED:    return (prev, INPUT_STALE, 2, mem)
if 해당 도어 approach:        return _approach(door, inp, mem)          # 3순위
if inp.state is FAULT:       return (prev, SENSOR_FAULT, 4, mem)
qm = _decide_qm(door, inp, prev)                                        # 6~12순위의 최상위 결과
if inp.values.crash is PENDING and qm.rank <= 11 and qm.lock is LOCK:
    return (prev, CRASH_PENDING, 5, mem)                               # 아래 순위로 넘어가지 않음 (CR-02)
return qm (memory=mem)
```

- 1·2·4순위는 상태 결정표와 조건이 같으므로 `state`로 판정한다.
- 3순위가 FAULT 검사보다 먼저 와서, 센서 고장 중에도 접근위험 잠금이 적용된다(Q-17).
- `qm.rank <= 11` 조건이 없으면 12순위(출력 유지)도 LOCK일 수 있다. 그 경우는 이미 유지이므로 CRASH_PENDING으로 바꾸지 않는다.

**`_approach(door, inp, mem) -> DoorDecision`** — 3순위, SWR-005·006. 복잡도 약 4

```text
if not _targets_unlock(door, inp.command):
    return (LOCK, OVERRIDE_REQUESTED if mem.override else APPROACH_RISK_LOCK, 3, mem)
if mem.suppressed_at_us is not None and inp.now_us - mem.suppressed_at_us <= OVERRIDE_WINDOW_US:
    return (LOCK, OVERRIDE_REQUESTED, 3, DoorMemory(mem.suppressed_at_us, True))
return (LOCK, APPROACH_RISK_LOCK, 3, DoorMemory(inp.now_us, False))     # 첫 요청 또는 10 s 초과 (Q-22)
```

**`_decide_qm(door, inp, prev) -> DoorDecision`** — 6~12순위. 복잡도 약 4

- 6~10순위를 규칙 표 `_QM_RULES`로 정의하고, 위에서부터 처음 맞는 규칙을 고른다.
- 표의 각 항목은 `(조건 함수(door, values) -> bool, Lock, Reason, rank)`이다.

| 순서 | 조건 함수 | 결과 |
|---|---|---|
| 1 | `not v.ignition_on` | RELEASE, IGNITION_OFF, 6 |
| 2 | `v.fire` | RELEASE, FIRE_RELEASE, 7 |
| 3 | `v.overtemp` | RELEASE, OVERTEMPERATURE_RELEASE, 7 |
| 4 | `isofix(door)` (도어별 필드 선택) | LOCK, ISOFIX_LOCK, 8 |
| 5 | `v.speed_kph >= AUTO_LOCK_SPEED_KPH` | LOCK, AUTO_LOCK_SPEED, 9 |
| 6 | `v.adult` | RELEASE, ADULT_PRESENT_RELEASE, 10 |

- 맞는 규칙이 없으면 `_decide_command(door, inp, prev)`를 호출한다.
- 표 안의 조건 함수는 각각 단위 시험으로 참·거짓을 모두 다룬다. 반복문의 "맞는 규칙 없음" 출구는 6개가 모두 거짓인 입력으로 다룬다.

**`_decide_command(door, inp, prev) -> DoorDecision`** — 11·12순위. 복잡도 약 4

```text
cmd = inp.command
if cmd is not None and _targets(door, cmd.side):
    return (LOCK, DRIVER_LOCK, 11) if cmd.action is lock else (RELEASE, DRIVER_RELEASE, 11)
return (prev, INPUT_INVALID if inp.any_invalid else NO_CHANGE, 12)
```

`_targets(door, side)`: `side is ALL` 또는 side가 door와 같다. `_targets_unlock(door, cmd)`: `cmd is not None`, unlock, `_targets(door, cmd.side)`.

**단위 시험 설계:**
- SWR-019 55쌍: 순위마다 단독으로 거는 입력 조각을 정의하고, 두 조각을 합쳐 `parametrize`로 만든다.
- SWR-019 세 규칙 조합 3개 (SWRS 표의 기대값)
- 좌/우 독립 (SWR-009)
- override 경계: 10,000,000 µs는 인정, 10,000,001 µs는 새 주기
- SWR-004 표의 행마다

## 9. U6 제어기 (`controller.py`) — SWR-010, 013~016, 019~021

```python
class ChildLockController:
    def __init__(self) -> None
    def tick(self, now_s: float, snapshot: object = None) -> Output
    def status(self) -> Output
    def events(self) -> tuple[DecisionRecord, ...]
```

**`tick`** — 복잡도 약 3. 계산 단계(1~5)에서는 self를 바꾸지 않는다.
1. `now_us = _to_now_us(now_s, self._last_now_us)`. DD-01을 어기면 `TickRejectedError`가 난다.
2. `parsed = validate_snapshot(snapshot)`
3. `tracker, view = advance_signals(self._tracker if self._tracker is not None else initial_tracker(now_us), parsed, now_us)`
4. `safety, state = advance_safety(self._safety, view, now_us)`
   - 이어서 `decision = arbitrate(ArbitrationInput(...))`
   - 이어서 `safety = apply_memory(safety, decision)`
5. `output = _build_output(decision, state, view, safety)`
6. 반영 단계: `_commit(...)`이 다음을 한 번에 한다.
   - `_last_now_us`, `_tracker`, `_safety`, `_output`을 갱신한다.
   - `parsed.present or _record_key(output) != _record_key(직전 output)`이면 `self._log.append(output, now_s)`를 호출한다.
   - `_record_key`는 (lock_left, lock_right, override_left, override_right, state)이다(SWR-010, CR-03).

**`_to_now_us(now_s, last_us) -> int`** — 복잡도 약 6. 아래 순서로 검사하고, 하나라도 어기면 `TickRejectedError`를 낸다.
1. `type(now_s) in (int, float)`이어야 한다(bool 제외).
2. float이면 `math.isfinite`를 검사한다. int에는 `isfinite`를 부르지 않는다(10^400에서 OverflowError가 나기 때문, DR-02).
3. `0 <= now_s <= NOW_MAX_S`. int와 float 비교는 정확하다.
4. `now_us = round(now_s * US_PER_S)`. 범위 검사를 통과한 값이라 오버플로가 없다.
5. `last_us`가 None이 아니면 `now_us > last_us`여야 한다.

**`_build_output(decision, state, view, safety) -> Output`** — 복잡도 약 4
- `priority = decision.left if decision.left.rank <= decision.right.rank else decision.right` (같으면 left)
- `reason_code = priority_reason = priority.reason`
- `input_validity`: `view.stale` → STALE, `view.any_invalid` → INVALID, 그 외 → VALID
- `warning_code`: `view.values.sensor_fault` → SENSOR_FAULT, 그 외 → NONE
- `override_*`는 `safety.mem_*.override`에서 가져온다.

**초기 상태:** `_output = INITIAL_OUTPUT`, `_tracker = None`(첫 틱에 `initial_tracker`), `_safety = SafetyState()`, `_last_now_us = None`

**단위 시험 설계:**
- now_s 위반: 같은 값, 과거, 0.4 µs 차이(반올림 후 같음), NaN, bool, −1, 1e9+1, 10^400
- 기록 조건: 입력 있음 / 입력 없이 DEGRADED 전이 / 입력 없이 reason만 바뀜(기록 없음) / 변화 없음
- 결정론: 같은 벡터를 두 인스턴스에서 재생해 출력이 같음
- 반영 원자성: `arbitrate`가 예외를 내도록 monkeypatch한 뒤 `status()`와 기록이 바뀌지 않음

## 10. U7 Web 인터페이스 (`web.py`, `__main__.py`) — SWR-015

```python
class _Handler(BaseHTTPRequestHandler)                               # 모듈 수준 처리기 (IC-03)
def make_handler(controller: ChildLockController) -> type[BaseHTTPRequestHandler]  # controller를 묶은 하위 클래스
def serve(host: str = "127.0.0.1", port: int = 8000) -> None      # HTTPServer (단일 스레드)
def main(argv: Sequence[str] | None = None) -> int                 # __main__.py에서 호출
```

| 요청 | 처리 |
|---|---|
| `GET /` | `importlib.resources`로 `static/index.html`을 읽어 200, text/html |
| `GET /api/status` | 200, `controller.status().to_dict()` |
| `GET /api/events` | 200, `[r.to_dict() for r in controller.events()]` |
| `POST /api/tick` | 본문 읽기(DD-03) → JSON 파싱 → 객체인지, `now_s` 키가 있는지 확인 → 실패하면 400. `snapshot` 키가 없으면 None(DD-02). `controller.tick` 호출. `TickRejectedError`이면 400. 성공하면 200, Output JSON |
| 그 밖의 경로 | 404 |
| GET·POST 외 메서드 | 501 (`BaseHTTPRequestHandler` 기본 동작, CR-08) |
| 위 처리 중 그 밖의 예외 | 500 (DD-04) |

- **직렬화:** `_serialize(payload) -> bytes`는 `json.dumps(payload, ensure_ascii=False).encode()`이다. 실패하면 예외가 나고 500으로 바뀐다.
  - 시험에서는 `childlock.web._serialize`를 monkeypatch해 `TypeError`를 일으켜 500을 확인한다.
- **로그:** `log_message`를 재정의해 요청 줄과 상태 코드만 남긴다. 본문은 남기지 않는다.
- **핸들러 메서드:** `do_GET`, `do_POST`, `_read_json_body`, `_send_json`, `_send_error`으로 나눠 각 복잡도를 6 이하로 둔다.
- **`_read_json_body` 오류 판정 (DR-17):**
  - Content-Length 문제(DD-03)는 400이다.
  - `body.decode("utf-8")`와 `json.loads`에서 나는 `ValueError`(`json.JSONDecodeError`, `UnicodeDecodeError` 포함)와 `RecursionError`는 400으로 바꾼다.
  - 이 예외들은 사용자 입력 오류이므로 DD-04의 500 대상이 아니다.

**시뮬레이터 화면 (`static/index.html`, SW 경계 밖)**
- 입력 13개 필드 폼과 명령 선택이 있다.
- 시각은 정수 틱 카운터 n으로 관리하고, `now_s = n / 100`, `timestamp_s = now_s`로 보낸다(DR-08).
- 명령은 한 틱에만 담아 보내고, 보낸 뒤 선택을 비운다(재입력이 저절로 생기지 않도록).
- "자동 진행"은 100 ms마다 명령 없이 현재 차량 입력으로 틱을 보낸다.
- 출력과 최근 기록을 표로 보여 준다.

**시험 설계:** 테스트에서 포트 0으로 실제 서버를 띄우고 `http.client`로 각 경로와 400·404·500 응답을 시험한다.
- 400 경우: UTF-8이 아닌 본문(`b'\xff{'`), 깊이 1,500단 중첩 JSON, 64 KiB + 1 바이트 본문, Content-Length 누락, now_s 10^400과 −0.5
- **Web 검증의 판정 근거 (DR-18):** 5단계 Web 시험의 합격 판정은 시뮬레이터 화면 표시가 아니라 `GET /api/status`, `GET /api/events` 응답으로 한다. 화면은 입력 편의 도구일 뿐이라 판정에 영향을 주지 않는다.
