# 정적 분석 계획: 전자식 차일드락 제어 SW

| 항목 | 내용 |
|---|---|
| 문서 ID | SAP-ECL-001 |
| 버전 | 1.0 (기준선 BL-SWD-1.0 후보) |
| 관련 | CLAUDE.md "소스코드 품질", SWA-ECL-001, SWD-ECL-001 |
| 프로세스 | A-SPICE SWE.3 (정적 검증 전략), SWE.4 |

## 1. 목적

구현(3단계)이 CLAUDE.md 품질 기준과 ISO 26262-6:2018 Table 1(모델링·코딩 지침 주제)을 만족하는지 정적으로 확인하는 방법과 합격 기준을 정한다.

## 2. ISO 26262-6 Table 1 대응

- **적용 원칙:** Table 1의 ASIL B 권고 등급(+, ++)은 원문 대조가 필요하다. 그래서 이 프로젝트는 **등급과 관계없이 1a~1i를 모두 적용**한다.
- 등급 확인은 교육 과정의 표준 원문으로 하고, 결과는 이 문서 개정으로 기록한다.

| Table 1 주제 | 이 프로젝트의 수단 |
|---|---|
| 1a 낮은 복잡도 강제 | Ruff C901 (순환복잡도 ≤ 10), `tools.check_metrics` (함수 50줄 이하) |
| 1b 언어 부분집합 사용 | 3절 Python 안전 부분집합 (자동 검출 + 리뷰) |
| 1c 강한 타입 사용 | 모든 함수에 타입 표기 (Ruff ANN), mypy strict + 명시적 Any 금지 |
| 1d 방어적 구현 기법 | 외부 입력은 C1에서만 받아 전부 검증. now_s 사전조건(DD-01). 예외를 400·500으로 바꿔 응답 없는 종료 방지(DD-04) |
| 1e 확립된 설계 원칙 사용 | 불변 데이터, 순수 함수, 단일 책임, 원자적 반영 (SWA AP-01~06) |
| 1f 모호하지 않은 그래픽 표현 | 설계 문서의 Mermaid 다이어그램 (의존도, 시퀀스, 상태도) |
| 1g 스타일 가이드 사용 | Ruff 포맷, Google Python Style Guide |
| 1h 명명 규칙 사용 | Ruff N (pep8-naming) |
| 1i 동시성 측면 | **해당 없음 논거:** 단일 스레드 HTTPServer(AD-03), `threading`·`asyncio`·`multiprocessing` 사용 금지(3절, 자동 검출) |

## 3. Python 안전 부분집합 (언어 부분집합)

| ID | 규칙 | 이유 | 검출 |
|---|---|---|---|
| PS-01 | `eval`, `exec`, `compile`, `__import__` 금지 | 동적 코드 실행은 정적으로 분석할 수 없음 | Ruff S307, S102, TID251 |
| PS-02 | `src/childlock`에서 `time`, `random`, `threading`, `asyncio`, `multiprocessing`, `os`, `subprocess`, `pickle` import 금지 | 결정론(AP-02), 단일 스레드(AD-03), 외부 영향 차단 | Ruff TID251 (banned-api) |
| PS-03 | `global`, `nonlocal` 금지 | 숨은 상태 | Ruff PLW0603, PLW0602, 리뷰 |
| PS-04 | 가변 기본 인자 금지 | 호출 간 상태 공유 | Ruff B006 |
| PS-05 | 예외 전체 삼킴 금지 (`except:`, 처리 없는 `except Exception`) | 고장 은폐. 단, DD-04의 500 변환 지점 1곳만 사유 주석과 함께 허용 | Ruff E722, S110, BLE001 |
| PS-06 | `assert`를 런타임 검사로 쓰지 않음 (테스트 제외) | `python -O`에서 사라짐 | Ruff S101 |
| PS-07 | None 판정은 `is None` / `is not None`만 사용 | 0, 빈 값의 참·거짓 오판 (DR-05) | 리뷰 |
| PS-08 | 시각과 경계는 정수 µs로 비교. float `==` 비교 금지 | 부동소수점 오차 (DR-01) | 리뷰, mypy 타입(int) |
| PS-09 | `setattr`, `delattr`, 몽키패치, 메타클래스를 제품 코드에서 쓰지 않음 | 정적 분석 무력화 | Ruff B010, 리뷰 |
| PS-10 | frozen dataclass 안에 가변 컨테이너를 그대로 두지 않음 | 불변성 (AP-04) | 리뷰, mypy (`Mapping` 타입) |
| PS-11 | set·frozenset의 반복 순서에 결과가 의존하지 않음 | 해시 순서에 따른 비결정성 | 리뷰 |
| PS-12 | 재귀 금지 | 스택 사용량 예측 | 리뷰 |

## 4. 도구와 설정 (3단계 시작 시 반영)

| 도구 | 설정 | 실행 명령 |
|---|---|---|
| Ruff | `select`에 `ANN`, `S`, `BLE`, `PLW`, `TID`, `RUF`, `B`를 둔다. `flake8-tidy-imports.banned-api`에 PS-02 모듈을 등록한다. `tests/`는 S101, ANN 일부를 허용한다 | `python -m ruff check .` |
| mypy (신규) | `strict = true`, `disallow_any_explicit = true`, `warn_unreachable = true`, `files = ["src", "tools"]` | `python -m mypy` |
| check_metrics | 변경 없음 | `python -m tools.check_metrics src tools` |
| pytest-cov | 변경 없음 (브랜치 100%) | `python -m pytest --cov --cov-branch` |

- mypy를 `requirements-dev.txt`에 버전 고정으로 추가한다.
- `Jenkinsfile`의 정적 분석 단계에 mypy를 넣고, CLAUDE.md 품질 게이트 목록에도 추가한다.
- **데드코드·데이터 흐름:**
  - Ruff F401·F841이 미사용 import와 변수를 잡는다.
  - mypy `warn_unreachable`이 도달할 수 없는 코드를 잡는다.
  - 브랜치 커버리지 100%가 실행되지 않는 분기를 잡는다.

## 5. 합격 기준

| 항목 | 기준 |
|---|---|
| Ruff | 위반 0건. `# noqa`는 사유 주석과 PR 리뷰 승인이 있는 것만 허용한다 |
| mypy | 오류 0건. `# type: ignore`는 Ruff noqa와 같은 조건으로만 허용한다 |
| 복잡도, 함수 길이, 주석률 | 위반 0건 |
| 브랜치 커버리지 | 100% |

## 6. 수동 리뷰 체크리스트 (PR마다)

- [ ] PS-07~PS-12를 지켰다.

- [ ] 예외를 삼키는 코드가 없다 (DD-04 지점 제외).
- [ ] import한 표준 라이브러리 모듈이 SWA-ECL-001 4.4절 허용 목록에 있다.

## 7. 도구 신뢰 수준 (ISO 26262-8 11절, 교육용 판단)

| 도구 | 용도 | TI | TD | TCL | 근거 |
|---|---|---|---|---|---|
| Ruff | 코딩 규칙 검출 | TI2 (규칙 위반을 놓칠 수 있음) | TD2 (PR 리뷰 체크리스트가 일부 재확인) | TCL2 | |
| mypy | 타입 검사 | TI2 | TD2 (단위 시험이 타입 오류의 결과를 상당 부분 검출) | TCL2 | |
| pytest | 시험 실행 | TI2 (실패를 통과로 보고할 수 있음) | TD1 (RED 단계에서 실패를 직접 확인하는 TDD 절차) | TCL1 | |
| pytest-cov | 브랜치 커버리지 측정 | TI2 | TD2 (리뷰에서 분기별 시험 존재 확인) | TCL2 | |

시뮬레이터 화면은 검증 도구로 쓰지 않는다. Web 시험 판정은 API 응답으로 하므로(SWD 10장) 이 표에 넣지 않는다.

TCL2 도구의 정식 적격성 확인(ISO 26262-8 11.4.6)은 교육 프로젝트 범위 밖이다. 대신 버전을 고정하고(`requirements-dev.txt`), 널리 쓰이는 도구라는 사용 실적을 근거로 기록한다.
