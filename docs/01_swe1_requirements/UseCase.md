# Use Case: 전자식 차일드락 제어 SW

| 항목 | 내용 |
|---|---|
| 문서 ID | UC-ECL-001 |
| 버전 | 1.0 (BL-SWR-1.0 후보) |
| 관련 문서 | SWRS-ECL-001 SW 요구사항 사양서 |

## 1. 행위자

| 행위자 | 설명 |
|---|---|
| 운전자 | 물리 버튼, AVN, 음성, 모바일 앱으로 잠금·해제 명령을 내린다 |
| 차량 | 차속, 기어, 충돌, 접근위험, 화재·과온, 성인 탑승, ISOFIX, 시동, 센서 고장 신호를 VehicleSnapshot으로 보낸다 |
| 시험자 | Web 시뮬레이터로 입력을 주입하고 상태와 기록을 확인한다 |
| 구동기 모델 | SW가 내보낸 좌/우 LOCK·RELEASE 논리 출력을 받는다 |

## 3. 상세 흐름

### UC-01 운전자가 차일드락을 잠그거나 해제한다
- **사전 조건:** state=NORMAL, ignition_on=TRUE
- **기본 흐름:**
  1. 운전자가 side(left/right/all)와 action(lock/unlock)을 골라 명령한다.
  2. SW는 명령 형식을 검사한다(SWR-013).
  3. lock이면 선택 도어를 LOCK으로 한다(SWR-001).
  4. unlock이면 해제 허용 조건(SWR-004)을 도어별로 판정해, 허용된 도어만 RELEASE로 한다(SWR-002).
  5. 결정 기록을 남긴다(SWR-010~012).
- **대체 흐름:**
  - 차속 ≥ 3.0 km/h에서 unlock: 거절(RELEASE_REJECTED_MOVING)
  - ISOFIX가 연결된 도어 unlock: 거절(RELEASE_REJECTED_ISOFIX)
  - 접근위험 도어 unlock: UC-03으로 진행
- **사후 조건:** 선택하지 않은 도어의 출력은 바뀌지 않는다(SWR-009).

### UC-02 출발하면 차일드락이 자동으로 잠긴다
- **사전 조건:** state=NORMAL
- **기본 흐름:** 유효 차속이 3.0 km/h 이상이 되면, 그 반영 주기에 좌/우 LOCK이 된다(SWR-003).
- **대체 흐름:**
  - 충돌 PENDING 중: 자동 잠금 미적용(SWR-008)
  - 화재·과온: RELEASE 우선(SWR-019 7순위)
  - 성인 탑승: 자동 잠금이 우선(Q-04)

### UC-03 하차 시 후측방 접근위험이 있으면 해제를 막는다
- **기본 흐름:**
  1. 왼쪽(또는 오른쪽) 접근위험이 TRUE가 되면 그 도어를 LOCK한다(SWR-005).
  2. 운전자가 그 도어를 unlock하면 억제하고, 처음 억제한 시각을 기록한다.
  3. 10.0 s 이하 안에 같은 도어를 다시 unlock하면 override 요청으로 인정한다(SWR-006). 접근위험이 TRUE인 동안 출력은 LOCK이다(Q-01). 센서 고장 중에도 같다(Q-17).
  4. 접근위험이 FALSE가 되면 override를 지우고 일반 규칙으로 돌아간다. 해제하려면 다시 unlock해야 한다(Q-20).
- **대체 흐름:** 10.0 s를 넘긴 재입력은 새 첫 요청으로 다시 억제한다.
- **사후 조건:** 반대쪽 도어는 영향을 받지 않는다(SWR-009).

### UC-04 충돌하면 차일드락을 긴급 해제한다
- **기본 흐름:**
  1. crash_status=CONFIRMED의 반영 주기에 좌/우 RELEASE, state=EMERGENCY가 된다(SWR-007). 같은 입력의 다른 필드에 오류가 있어도 적용한다(Q-19).
  2. 이후 어떤 입력에도 RELEASE를 유지한다.
  3. crash_status가 CONFIRMED가 아니고 시동이 1.0 s 이상 연속으로 꺼지면 래치를 지운다(Q-06).
- **대체 흐름:** PENDING이면 QM 규칙(ISOFIX, 자동 잠금, 운전자 LOCK)의 새 LOCK만 적용하지 않는다. 접근위험 잠금과 모든 해제는 적용한다(SWR-008).

### UC-05 화재·과온·성인 탑승이면 강제 해제한다
- **기본 흐름:** fire_detected, overtemperature_detected, adult_present 중 하나라도 TRUE이면 반영 주기에 좌/우 RELEASE가 되고, 입력별 이유 코드를 남긴다(SWR-017).
- **대체 흐름:**
  - 접근위험 도어는 LOCK을 유지한다(Q-02).
  - 성인 탑승만 TRUE이면 ISOFIX 도어와 차속 3.0 km/h 이상에서는 해제하지 않는다(Q-03, Q-04).
  - 센서 고장 중에는 출력을 유지한다(Q-18, 잔여 위험).

### UC-06 ISOFIX가 연결된 쪽을 강제로 잠근다
- **기본 흐름:** isofix_left(또는 right)가 TRUE이면 해당 도어만 LOCK한다. 반대쪽은 유지한다(SWR-018).
- **대체 흐름:** 강제 해제 조건이면 RELEASE가 우선한다(Q-03).

### UC-07 시동을 끄면 차일드락을 해제한다
- **기본 흐름:** ignition_on=FALSE의 반영 주기에 좌/우 RELEASE, state=OFF가 되고, override를 지운다(SWR-020). EMERGENCY 래치는 SWR-007의 해제 조건으로만 지운다.
- **대체 흐름:** 센서 고장 중이거나 접근위험 도어가 있으면 ASIL B 규칙을 따른다(Q-16).

### UC-08 입력 이상·센서 고장에 안전하게 대응한다
- **기본 흐름:**
  1. 형식·범위 오류 필드는 직전 유효값으로 대체하고, 잘못된 운전자 명령은 그 명령만 거절한다(SWR-013).
  2. 판정 필드 중 하나라도 200 ms를 넘게 갱신되지 않으면, 입력이 없는 틱에서도 100 ms 안에 DEGRADED가 된다(SWR-013). 입력 끊김, 특정 필드의 지속 오류, 역순 프레임이 모두 해당한다.
  3. sensor_fault=TRUE이면 출력을 유지하고 FAULT와 경고 코드를 낸다. 충돌 해제와 접근위험 잠금은 예외다(SWR-021).
  4. 정상 입력이 돌아오면 상태 결정표에 따른 상태로 복귀한다(Q-10).

### UC-09 시험자가 상태와 결정 기록을 확인한다
- **기본 흐름:**
  1. 시험자가 Web 시뮬레이터로 시뮬레이션 시각(now_s)과 VehicleSnapshot(또는 없음)을 보낸다.
  2. SW는 한 틱을 판정하고 출력을 JSON으로 돌려준다(SWR-015).
  3. 시험자가 상태(SWR-014)와 최근 100건 기록(SWR-012)을 조회한다.
- **대체 흐름:**
  - 요청 형식이 틀리거나 now_s가 증가하지 않으면 HTTP 400을 돌려준다.
  - 응답 직렬화에 실패하면 HTTP 500을 돌려준다.

### UC-10 같은 입력을 재생해 같은 결과를 확인한다
- **기본 흐름:** 고정 시계로 만든 입력 벡터를 새 인스턴스에서 반복 재생하면, 모든 틱 출력의 해시가 매번 같다(SWR-016).
